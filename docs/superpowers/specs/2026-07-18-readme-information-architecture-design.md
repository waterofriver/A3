# 智学引擎 README 信息架构设计

## 目标

更新仓库内全部 README，使其忠于当前项目实现，同时满足三类读者：

1. 评委能够快速理解赛题价值、核心功能、创新点、技术实现和交付完整度。
2. 开发者能够安装、运行、测试、部署和继续开发项目。
3. 团队或 AI 能够从 README 中提取准确事实，用于后续编写系统开发说明、测试说明、PPT 和演示材料。

README 不替代正式作品文档，也不按照评分表机械堆砌内容。它应保持正常软件仓库 README 的可读性、可操作性和事实边界。

## 信息来源与真实性规则

内容按以下优先级核对：

1. 当前源码、路由、数据模型、配置和测试。
2. `docs/components.md`、`docs/api-integration.md`、`docs/deployment.md`、`docs/demo-script.md`。
3. 已确认的平台设计规格和历次对话总结。
4. 用户提供的赛题说明，用于解释项目价值和需求对应关系，不用于虚构未实现功能。

必须区分：

- 已实现、可运行的功能。
- Mock 模式的可验证演示能力。
- 已实现接口但依赖外部 Agent 或真实媒体的能力。
- 后续扩展方向。

不得把框架、占位接口或设计方案写成已经交付的真实多模态生成结果。不得声称尚未验证的防幻觉准确率、生成性能或业务效果数据。

## README 分工

### 根 `README.md`

根 README 是项目总入口，保留原 README 的信息密度并完善为以下结构：

1. 项目名称、定位和赛题背景。
2. 面向高校个性化学习的痛点、解决方案和实用价值。
3. 已实现能力：六维画像、五类资源、多 Agent 任务、学习路径、答疑、评估、记忆、知识库和错误恢复。
4. 赛题需求对应关系，以自然的功能表说明“需求、实现、证据入口”，不复制整份赛题原文。
5. 创新点：学习闭环、统一任务事件、局部失败保留、知识图谱与记忆助手、Mock/Remote 显式边界、沉浸式展示页。
6. 系统架构、多智能体协作和核心数据流。
7. 技术栈及主要开源依赖，说明用途；许可证细节链接到项目许可证和依赖清单。
8. 完整项目结构，至少覆盖前端、后端、Agent、知识库、基础设施、文档、产物和启动脚本。
9. 本地运行、Docker Compose、云部署与 HTTPS 提示。
10. 环境变量、Agent 模式和真实外部输入。
11. 测试命令、演示证据、已知限制和文档索引。
12. AI Coding 使用说明：说明项目开发过程中使用 Codex/Claude Code 类工具辅助设计、编码、测试和文档，但最终内容由项目代码与测试验证。

### `backend/agent/README.md`

保留本地八类 Agent 的完整目录、职责、输入输出、资源类型映射、DeepSeek 配置、测试方法和网关集成关系。明确：

- 本地 Agent 代码真实存在。
- 当前活动网关默认支持 `mock` 与 `remote`，`local` 仅在显式配置和依赖就绪时使用。
- 前端资源枚举与 Agent 输出之间需要经过网关契约转换。
- 视频路径和阅读文件路径必须转换为安全的 HTTP `media_url`，不能直接暴露磁盘路径。

删除或修正不存在的文件、接口和“待复制回来”等过时说法。

### `knowledge_base/README.md`

保留知识库搭建指南的教学性和完整度，包括：DAG 概念、字段说明、目录示例、支持格式、素材组织、校验、元数据生成、运行时同步、文件大小和交付清单。以当前真实课程 `robot-safety` 和顶层知识库为准。

### `artifacts/README.md`

保留 11 张截图、演示录屏、视口基准、生成命令和检查标准。补充沉浸式登录页的最新情况，并明确哪些产物提交、哪些日志/trace/临时截图由 `.gitignore` 排除。

### `backend/agent/knowledge_base/README.md`

说明该目录是本地 Agent 模板参考，不是当前运行时知识库，但保留模板字段、最小示例和迁移到顶层 `knowledge_base/` 的方法。避免与顶层完整指南重复。

## 写作要求

- 中文为主，保留必要的英文技术名称和命令。
- 先讲项目价值和能力，再讲实现与运行；避免以安装命令开篇。
- 表格只用于精确映射，长篇解释使用短段落。
- 每项能力都能链接到源码目录、API 文档、组件文档或演示证据之一。
- 保留必要细节，不复制 API 文档和组件文档的全部内容。
- 使用相对链接，确保 GitHub 和打包文件中都可访问。
- 不写临时端口、进程 PID、个人绝对路径或本地一次性状态。

## 验证

完成后执行：

1. `git diff --check`。
2. 枚举全部 README，确认五份均已更新。
3. 校验 README 中的相对链接和命令所引用的文件存在。
4. 检索过时术语和虚假承诺，例如已删除的 Django/Coze 活动路径、不存在的 provider 文件、伪造媒体或未验证性能数字。
5. 对照当前路由、API 路由、Agent 目录和赛题核心要求进行人工复核。

## 非目标

- 不创建系统开发说明书、测试说明书、PPT 或其他作品文档。
- 不修改业务代码、配置、数据库或部署行为。
- 不为了“看起来完整”宣称尚未接入的外部 Agent、媒体生成服务或安全审核服务已经上线。
